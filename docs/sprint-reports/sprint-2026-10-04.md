## Retrospective

The team shipped everything it planned; the main lessons are about board hygiene and merging earlier.

### What went well

- **Plan first, then build.** The TRD, page designs and proofs of concept (29 items) were done before feature work, so every page started from an agreed design and data contract.
- **Mock API mode.** The frontend was built and demoed against a mock backend while the API was still being written, then switched to the real API page by page.
- **Contract tests before endpoints.** API contract tests were written first, so each endpoint had a clear definition of done.
- **Guard rails on every commit.** Linting, type checks, unit tests and commit-message rules run before each commit.
- **Clear ownership.** Each person owned distinct areas, which kept merge conflicts low.

### What to improve

- **Check runtime limits before writing curriculum tasks.** The Prisma course (8 days, 16 tasks) was built for the in-browser runtime, but the Prisma command-line tool can't run there. This was only found at the end of the sprint, so the course ships as write-only.
- **Link pull requests to issues.** 80 of the 144 done items have no linked pull request, so the board can't show what shipped where.
- **Merge in smaller steps.** Six backend features (dashboard, tasks, flags, activity time, typing history, journal) and the deployment merged on go-live day, leaving little time to catch integration problems.
- **Don't leave documentation until the end.** Documentation, the sprint report and the release notes were all written in the last two days.

## Proposed next sprint

1. **Code validation (#234, #250):** check a task's code on the server before it is marked completed, following the validation design. HTML, CSS and SQL checks first; Node.js tests need a sandbox and come later.
2. **QA follow-ups (#246–#249):** flag durations, Prisma Day 4 reference page, hardening and one rule for locked days.
3. **Runnable Prisma tasks:** choose and build a way to run the Prisma course, since the Prisma command-line tool can't run in the in-browser runtime. Options: a server-side sandbox for Prisma tasks, a pre-built Prisma client connected to the in-browser database (PGlite), or a local setup guide for those 8 days. Start with a one-day spike to compare them.
4. **Mentor dashboard:** each trainee's current day, progress, time and focus records, which are stored but can't be viewed yet.
5. **Trainee management,** so mentors can enrol trainees without a code change.
6. **Board hygiene:** every item assigned, every PR linked, statuses updated daily.
