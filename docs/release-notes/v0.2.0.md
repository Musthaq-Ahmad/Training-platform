# Vinkup v0.2.0 (beta) — Release notes

_9 October 2026 · vinkup.netlify.app_

Vinkup v0.2.0 gives mentors their own side of the platform. Mentors sign in with the same company
Google account flow and land on a dashboard of every trainee. From there they can spot who needs
attention, open any trainee's code, journal and focus records, add new trainees and print a
progress report. Trainees get course certificates, a journal page, a help page, a day integrity
score and a light/dark theme.

## Highlights

- **A mentor dashboard.** Every trainee in one table with progress, current day, time, typing speed,
  integrity score and last activity, plus cohort totals at the top.
- **Find who needs attention.** Search, sort and a _Needs attention_ filter flag trainees who are
  inactive, behind the cohort or have a low integrity score.
- **A full view of each trainee.** Their stats, course-by-course progress, submitted code (read-only),
  journal entries and focus records, on one page.
- **Mentors manage the cohort.** Add a trainee from the dashboard, export the list as CSV, and print
  or save a trainee's progress report as a PDF.
- **Course certificates.** Finishing every day of a course earns a printable certificate with its own
  certificate ID.
- **An integrity score.** Each day gets a score out of 100 based on the focus records, shown to the
  trainee on the day page and averaged for mentors.

## How the integrity score works

The score is a guide for review, not proof, and it never blocks a trainee.

- **Per task:** start at 100 and take points off for each focus event on that task:
  - a blocked paste: 10 (at most 5 per task count);
  - a tab switch: 3, plus 1 per full minute away, up to 9;
  - leaving fullscreen: 4, plus 1 per full minute away, up to 11;
  - moving to another window: 1 (only the first 2 window changes per task count, short ones
    included).

  Tab switches and window changes shorter than 10 seconds cost nothing. Each penalty is multiplied
  by the event's review priority: low ×1, normal ×1.5, high ×2. A task never goes below 0.

- **Per day:** the average of the scores of the day's tasks the trainee worked on (saved code or any
  focus event), rounded. A day with nothing started has no score yet. The trainee's day badge is
  green from 90, amber from 75 and red below 75.
- **Per trainee (mentor view):** the average of their day scores. _Needs attention_ flags an average
  below 75.

## Changes and fixes

- **One rule for locked days.** Every page and endpoint now uses the same rule: a day is open if it
  is completed, is the first day, or the day before it is completed.
- **Focus event durations** are now stored in milliseconds, as the field name says. Earlier records
  were 1000 times too small.
- **Trainees who haven't started** are no longer flagged as inactive.
- **Mentors see only submitted work:** the trainee's task list shows the tasks they have submitted,
  in curriculum order, and the code viewer says when a task still has only its starter code.
- **Wrong-role access is refused.** Trainee pages and endpoints answer 403 to mentors, and mentor
  pages and endpoints answer 403 to trainees. The app sends each role to its own home page.
- **Daily activity bars** are scaled to an 8-hour day.

## Access and data

- **Two kinds of account.** Mentors are kept in a separate `admin` list; trainees in the trainee
  list. If an email is in both, it signs in as a mentor.
- **Mentor access is checked on every request.** A mentor account that is switched off loses access
  at once, even with a valid session.
- **Mentors can read every trainee's data, but not change it.** The only thing a mentor can create is
  a new trainee. Code, progress, journal and focus records are read-only to mentors.
- **Focus records are never shown to the trainee as a list**, only as their day score.
- **Adding mentors** is still done by the development team (see Known limitations).

## Requirements

No change from v0.1.0: a laptop or desktop with an up-to-date Chrome or Edge, fullscreen allowed,
and a steady internet connection. Printing reports and certificates works in any browser; the page
numbers and repeating footer on the progress report need Chrome or Edge 131 or later.

## Known limitations

v0.1.0's two biggest gaps, no mentor screen and no way to add trainees, are closed. These remain.

**Mentors and access**

| Limitation                                     | Effect                                                                                          | Workaround for now                                                        |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Mentors can't be added in the app              | New mentor accounts need a change to the setup script, or a row added to the `admin` table      | Ask the development team                                                  |
| Trainees can't be removed or deactivated       | A trainee who leaves stays in the list and the cohort totals                                    | The development team can remove the trainee from the database             |
| No feedback or messages from mentor to trainee | Mentors can read submitted code but can't comment on it or mark it reviewed in the app          | Give feedback in person or over chat                                      |
| Flags can't be marked as reviewed              | Every flag stays in the list and in the score, however it was explained                         | Read the score together with the flags and the trainee's work             |
| One email opens one side                       | An email in both lists always opens the mentor side                                             | Switch the admin row off, or use another account, to try the trainee side |
| Commercial licence for the in-browser runtime  | Unchanged from v0.1.0: StackBlitz requires a licence for production use in a commercial setting | Confirm with StackBlitz before rolling out beyond the beta                |

**Integrity score and focus records**

| Limitation                              | Effect                                                                                                                             | Workaround for now                                  |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| The score is a guide, not proof         | It comes from tracking in the trainee's browser: opening DevTools counts as leaving the window, and offline events aren't recorded | Read it with the flags, the code and the time spent |
| Older focus records have tiny durations | Events recorded before the millisecond fix count as very short, so they cost fewer points                                          | None needed; new events are recorded correctly      |
| Screenshots can't be blocked            | Unchanged from v0.1.0                                                                                                              | A policy matter for the mentor                      |

The curriculum, workspace and Prisma limitations from [v0.1.0](v0.1.0.md#known-limitations) are
unchanged: changing a Prisma schema empties its database, some Prisma CLI commands don't run, native
packages don't install, there are no automatic checks before submission, SQL and Prisma databases
live only in the trainee's browser, and the web preview can't use local images, fonts or video.

## Future scope

None of these is committed yet.

**For mentors**

1. **Review and feedback** — comment on a submission, mark it reviewed, and let the trainee see the
   feedback.
2. **Trainee management** — deactivate a trainee in the app.
3. **Mark flags as reviewed**, with a note, and leave them out of the score.

**For Trainee Experience and Curriculum**

4. **Automated task validation** — Run task-specific tests during submission and provide immediate feedback.
5. **Live code preview**, Support side-by-side previews for applicable task types.
6. ** First-login walkthrough** : Guide trainees through the dashboard, workspace, journal, and submission process.

**For the workspace**

6. **Web quality tools**, **media in the web preview**, **more than one terminal** and **PGlite in a
   background worker**, carried over from v0.1.0.

**For the platform**

7. **Licence decision** for the in-browser Node.js runtime.
8. **Dependency caching**. Cache installed node_modules in the browser, keyed by a hash of each course’s package.json and lockfile, so Node, TypeScript, and React tasks start quickly without reinstalling packages every time.

## Under the hood

The [architecture overview](../architecture-overview.md) and the
[API reference](../api-specifications.md) have the details.

| Change         | What                                                                                                                                                                                |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Database       | New `admin` table (email, name, active flag, last sign-in). No other schema changes                                                                                                 |
| Sessions       | The session token now carries the role (`trainee` or `admin`); `/api/auth/me` returns it                                                                                            |
| API            | 7 new endpoints: 5 under `/api/admin` (list, detail, flags, task code, add trainee), the day integrity score and the course certificate. `/api/dashboard` adds `completedCourseIds` |
| Route guards   | `requireTrainee` and `requireAdmin` replace the single sign-in check; `requireAdmin` also checks that the mentor account is still active                                            |
| Frontend       | Role-based routing, the mentor pages, certificate pages, journal and help pages                                                                                                     |
| Quality checks | Unchanged: unit tests, API contract tests (now including role-guard tests), type checks and linting on every commit                                                                 |
