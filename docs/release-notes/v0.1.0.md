# Vinkup v0.1.0 (beta) — Release notes

_Live since 3 October 2026 at vinkup.netlify.app_

Vinkup v0.1.0 is the first beta of our in-house trainee training platform. Trainees sign in with their
company Google account and work through an 8-course, 54-day curriculum one day at a time. They write
and run code in the browser, and every trainee's progress is saved on the server.

## Highlights

- **A guided path, one day at a time.** 54 days across HTML, CSS, JavaScript, TypeScript, Node.js,
  PostgreSQL, Prisma and React. Each day unlocks when the previous one is submitted.
- **Code without installing anything.** Web pages, Node.js projects and SQL all run inside the
  browser, with an editor, a file tree, a terminal and a live preview.
- **Work is never lost.** Code saves automatically a few seconds after typing stops, and on every
  device the trainee picks up where they left off.
- **Progress at a glance.** A dashboard shows the next day, days completed, time spent and typing
  speed. A profile page adds daily activity and typing history.
- **Focused practice.** The platform runs fullscreen and pasting is turned off in the code editor.
  Leaving fullscreen or switching tabs is recorded for the mentor.

## How progress works

Trainees move through the curriculum in order, and the server enforces it: a locked day or task can't
be opened by typing its address.

- **Days unlock one at a time.** The first day not yet submitted is open; every day after it is
  locked. Finished days stay open to revisit. The order runs across courses, so HTML Day 5 leads to
  CSS Day 1.
- **Tasks have three states.** Not started → in progress after the first save → completed after
  Submit. Editing a completed task keeps it completed, and it can be resubmitted any time.
- **Submit Day needs every required task submitted.** Stretch goals are optional. The self-check list
  is for the trainee's own review and isn't checked. On success the next day unlocks and the page
  offers a link straight to it.
- **Autosave.** Code saves 2 seconds after typing stops (at most 8 seconds apart while typing
  nonstop), on Ctrl/Cmd+S, and when leaving the page or switching tabs. The browser warns before
  closing with unsaved work. Offline edits save as soon as the connection returns. A file too large
  for the server is named in the save indicator instead of failing silently.

## Focus and integrity

The platform is built for focused, hands-on practice, and records the moments a trainee steps away.
Trainees are told this on the fullscreen screen.

- **Fullscreen only.** Once signed in, the whole platform is covered until the trainee enters
  fullscreen.
- **No pasting in the workspace.** Paste is turned off in the code editor and the terminal; trying it
  shows a short warning and is recorded.
- **What is recorded, per task:** leaving fullscreen, switching browser tabs, moving to another
  window, and blocked pastes, each with the time it started.
- **Time:** _active time_ counts while the platform is visible and the trainee has used the mouse or
  keyboard in the last 5 minutes; _coding time_ counts while they are working in a task (editing,
  running, using the terminal) and for a minute after. Both are totalled per calendar day, India time.

The records are stored per trainee. There is no mentor screen to view them yet, and they are a guide
rather than proof (see Known limitations).

## Access and data

Only enrolled trainees with a company email can sign in, and each trainee sees only their own work.

- **Sign-in** is Google only. Two checks apply: the email must be on the company domain, and the
  person must be on the trainee list. Anyone else gets a clear message instead of an empty account.
- **Sessions** last up to 7 days, then the trainee signs in again.
- **Per trainee, the platform stores:** their code for each task, task and day completion with times,
  journal entries, typing results, daily active and coding time, and focus records.
- **Every request is tied to the signed-in trainee** on the server, so one trainee can't read or
  change another's data.
- **Enrolling a trainee** is done by the development team for now (see Known limitations).

## Requirements

Vinkup needs a laptop or desktop with a recent Chrome or Edge.

| Need                            | Why                                                                                                                    |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Chrome or Edge, kept up to date | Node.js tasks run inside the browser using features these two support fully; Safari and older Firefox may not run them |
| A laptop or desktop             | The workspace is built for a keyboard and a large screen; phones and tablets aren't supported                          |
| Fullscreen allowed              | The platform only runs fullscreen                                                                                      |
| A steady internet connection    | Code saves to the server; Node.js tasks download their packages on first run                                           |
| One tab at a time               | Only one in-browser Node.js runtime can start per tab, and several tabs compete                                        |
| Ad blockers off for the site    | Some block the services the in-browser runtime downloads from                                                          |

## Known limitations

The biggest gaps are that mentors can't see progress or focus records in the app yet, and that the
Prisma course can't run its code in the browser. The rest are minor or have a workaround.

**Platform and access**

| Limitation                                                        | Effect                                                                                            | Workaround for now                                                  |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| No mentor or admin screen                                         | Progress, time and focus records are stored but can't be viewed in the app                        | The development team can pull a report from the database on request |
| Enrolling trainees needs the development team                     | Adding someone means a small code change and a re-run of the setup script                         | Send the team the names and emails before each batch starts         |
| Commercial licence for the in-browser Node.js runtime unconfirmed | The runtime's provider (StackBlitz) requires a licence for production use in a commercial setting | Confirm with StackBlitz before rolling out beyond the beta          |

**Curriculum and tasks**

| Limitation                            | Effect                                                                                                                                                                                        | Workaround for now                                                  |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Prisma tasks can't run in the browser | The Prisma command-line tool (`prisma generate`, `prisma migrate`, `prisma db push`) doesn't run in the in-browser Node.js runtime, so the Prisma course can be written and saved but not run | Trainees run Prisma tasks on a local setup; mentors review the code |
| No automatic check before submission  | Submit marks a task completed whether or not the code works                                                                                                                                   | Mentors review submitted code                                       |

**Workspace**

| Limitation                                          | Effect                                                                                                                                                 | Workaround for now                                                           |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| SQL tables are stored only in the trainee's browser | The SQL files save to the server, but the tables and rows don't: another browser, a private window or cleared site data starts from the starter tables | Re-run the task's SQL files; **Reset database** returns to the starter state |
| Local images, fonts and video in the web preview    | Workspace files are text only: a task can use SVG files and images from web addresses (https), but can't include its own PNG, JPG, font or video files | Use SVG, or images hosted online                                             |

**Focus records and data**

| Limitation                                      | Effect                                                                                                                                              | Workaround for now                                         |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Focus records are a guide, not proof            | Tracking runs in the trainee's browser: opening browser DevTools counts as leaving the window, and events that happen while offline aren't recorded | Read the records together with the trainee's work and time |
| Screenshots can't be blocked                    | Browsers don't let a web page stop screenshots or screen recording                                                                                  | None in the browser; it is a policy matter for the mentor  |
| "Reading & lessons" on the profile is estimated | It is total time minus coding time, not measured reading                                                                                            | Read it as a rough figure                                  |

## Future scope

None of these is committed yet; the order within each group is a suggestion for the product owner to
set.

**For mentors**

1. **Mentor dashboard** — each trainee's current day, completed days, time per day and focus records,
   in one view.
2. **Trainee management** — mentors add or deactivate trainees without the development team.
3. **Journal showcase** — a page where mentors read trainees' daily journals.

**For the curriculum**

4. **Runnable Prisma tasks** — the Prisma command-line tool can't run in the in-browser runtime; options
   are a server-side sandbox for Prisma tasks, a pre-built Prisma client connected to the in-browser
   database (PGlite), or a local setup guide for those 8 days.
5. **Checks before submission** — run each task's tests or checks when the trainee submits, and show
   what failed.

**For the workspace**

6. **Web quality tools** — HTML validation (W3C), Lighthouse and browser DevTools-style inspection
   inside the workspace.
7. **Media in the web preview** — let trainees add PNG, JPG, font and video files to a task.
8. **More than one terminal** per task.
9. **PGlite in a background worker**, so long SQL queries never freeze the page.

**For the platform**

10. **Licence decision** for the in-browser Node.js runtime.
